## 1. 現状デモと本番要件のギャップ分析

デモは「画面と業務フローの合意形成」が目的のフロントエンド実装であり、本番稼働には以下の実装が必要。

| # | 機能 | デモの現状 | 本番で必要な実装 | 重要度 |
|---|------|-----------|----------------|--------|
| 1 | データ永続化 | localStorage保存（デモ実装済・端末単位） | DB（PostgreSQL）への保存 — localStorageは同一ブラウザ内のみで、学生と企業が別端末から同じデータを見ることはできない | 必須 |
| 2 | 認証・アカウント | なし（画面切替のみ） | 学生／企業／運営の3ロール認証 | 必須 |
| 3 | 企業の学生情報閲覧 | 誰でも閲覧可 | **審査承認済み企業のみ**閲覧可（アクセス制御） | 必須 |
| 4 | 最新情報の通知 | 画面内フィードのみ（デモ実装済） | DB変更→アプリ内通知＋メール通知の自動配信 | 必須 |
| 5 | 運営審査フロー | 登録＝即公開 | 申請→運営審査→承認→公開のステータス管理 | 必須 |
| 6 | 保護者同意（高校生） | チェックボックスのみ | 同意書アップロード＋運営確認ステータス | 必須 |
| 7 | 動画 | URL入力のみ | YouTube限定公開の埋め込み表示＋URL検証 | 推奨 |
| 8 | 画像（顔写真） | 縮小してlocalStorageに保存（デモ実装済） | Storage保管＋掲載前の運営審査＋非公開バケット | 必須 |
| 9 | 支援相談（目星→事務局） | 相談フォーム→事務局画面に案件表示（デモ実装済） | 事務局へのメール即時通知＋案件管理DB | 必須 |
| 10 | 監査ログ | なし | 閲覧・変更ログ（未成年情報保護の観点で重要） | 推奨 |

## 2. 推奨アーキテクチャ

個人事業での初期運用を前提に、**フロントエンド静的ホスティング＋BaaS（Supabase）** 構成を推奨。

```
[学生/企業ブラウザ]
      │ HTTPS
[フロントエンド]  GitHub Pages または Vercel（現行RELIGHTサイトと同運用）
      │ supabase-js
[Supabase]
  ├ Auth        … メール認証＋ロール管理（student / company / admin）
  ├ PostgreSQL  … 全データ（下記スキーマ）
  ├ RLS         … 行レベルセキュリティでアクセス制御（§4）
  ├ Realtime    … フォロー中学生の更新をアプリ内フィードへ即時配信
  ├ Storage     … 保護者同意書PDF・プロフィール画像
  └ Edge Functions … メール通知（Resend連携）・週次ダイジェスト
```

選定理由：サーバー管理不要、無料枠で検証開始でき、月額課金後も小規模なら数千円台。認証・DB・通知が一体で、開発量が最小。

## 4. 「企業が最新の学生情報を確認できる仕組み」の本番設計

デモで実装した更新フィードを、本番では次の3層で実現する。

1. **閲覧権限（RLS）**：`companies.status = 'approved'` の企業のみ `students`（status=approved）を SELECT 可能。学生本人は自分の行のみ UPDATE 可能。未承認企業・未ログインには一切表示しない。
2. **即時反映（Realtime＋トリガー)**：学生がマイページを保存すると DB トリガーが変更種別を判定して `notifications` に行を挿入。フォロー中企業のフィードに Realtime で即時配信（デモの「NEW」バッジと同じ体験）。
3. **メール通知（Edge Function）**：記録更新・戦績追加は即時メール、その他は週次ダイジェストに集約。配信頻度は企業側で設定可能にし、通知疲れによるフォロー解除を防ぐ。

## 5. 審査・公開フロー（ステータス遷移）

```
学生：申請(pending) → 運営審査[本人確認/所属確認/戦績確認/連盟規定確認]
     → (高校生のみ) 同意書確認(waiting→verified) → 公開(approved)
企業：申請(pending) → 運営審査[実在確認/反社チェック] → 承認(approved)
                                  └ 承認まで学生情報は閲覧不可
```

## 6. セキュリティ・法務要件の実装対応

- 高校生プロフィールには「保護者同意済み」バッジを表示（デモ実装済）。同意書は Storage の非公開バケットに保管し、運営のみアクセス可。
- 連絡先（メール等）は企業に直接表示しない。コンタクトは必ず `inquiries`（運営経由）を通す — 直接取引による手数料回避の防止と、未成年保護を兼ねる。
- 監査ログで「どの企業がどの学生をいつ閲覧したか」を記録（未成年情報の取扱いに関する説明責任）。
- 動画はYouTube埋め込みのみ許可（自前ホスティングは容量・権利リスクが大きい）。
