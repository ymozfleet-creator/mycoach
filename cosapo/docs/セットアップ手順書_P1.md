# コサポ P1 セットアップ手順書

対象ファイル：`cosapo_schema.sql`（データベース）／`cosapo_app.html`（アプリ本体）
所要時間：約30〜40分。プログラミング作業は不要で、コピー＆ペーストと画面操作のみです。

---

## §1. Supabaseプロジェクトの作成（約5分）

1. https://supabase.com にアクセスし、GitHubアカウント等でサインアップ
2. 「New Project」→ 以下を入力
   - Name：`cosapo`
   - Database Password：強力なものを生成して**必ず保管**
   - Region：`Northeast Asia (Tokyo)`
3. 作成完了まで1〜2分待つ

料金：Freeプランで検証・初期運用が可能。本格運用時にProプラン（約$25/月）へ。

## §2. データベースの構築（約5分）

1. 左メニュー「SQL Editor」→「New query」
2. `cosapo_schema.sql` の中身を**全文コピーして貼り付け**、「Run」
3. 続けて `admin_emails.sql` も同様に実行（事務局画面に連絡先メールを表示するための関数。運営アカウントにのみメールを開示します）
4. **既にv1.0のSQLを実行済みのDBの場合**：`migration_v1_1.sql` を1回実行してください（セキュリティ強化の移行。新規構築なら不要）
3. 「Success. No rows returned」と出れば完了（テーブル10個・アクセス制御25ポリシーが作成されます）

これで以下がすべて設定されます：
- 学生・企業・チェック・通知・支援相談・監査ログの全テーブル
- アクセス制御（RLS）：**「学生には誰がチェックしたか見えない」がDBレベルで保証**されます（学生に読み取り権限が存在しないため、画面改造でも突破不可）
- 学生は自分のステータス（審査中/公開中）を自分で変更できない制御
- 野球の登録をDB制約でも遮断（画面と二重のポカヨケ）
- 顔写真用ストレージと本人フォルダのみ書込可の権限

## §3. アプリの接続設定（約3分)

1. Supabaseの「Project Settings」→「API」を開く
2. `Project URL` と `anon public` キーをコピー
3. `cosapo_app.html` をテキストエディタで開き、冒頭付近の以下を書き換えて保存：

```js
const CONFIG = {
  SUPABASE_URL: "https://xxxxx.supabase.co",   // ← Project URL
  SUPABASE_ANON_KEY: "eyJhbGci..."             // ← anon public キー
};
```

※anonキーはブラウザに公開してよい前提のキーです（アクセス制御はRLSが担うため）。`service_role` キーは**絶対にHTMLに書かないでください**。

## §4. 検証しやすくする一時設定と運営アカウント（約5分）

1. 「Authentication」→「Sign In / Up」→ Email の「Confirm email」を**一時的にOFF**（確認メールなしで検証できる。公開時にONへ戻す）
2. `cosapo_app.html` をブラウザで開き、「新規登録」から運営用メールアドレスでアカウント作成（種別はどちらでも可）
3. SQL Editorで以下を実行して運営権限に昇格：

```sql
update public.profiles set role='admin'
where id = (select id from auth.users where email = '運営のメールアドレス');
```

4. アプリを再読み込み→ログインすると「事務局管理」画面が表示されます

## §5. 動作テスト（約10分）

別のメールアドレス（またはブラウザのシークレットウィンドウ）で一気通貫を確認：

1. **学生**：新規登録（種別=学生）→ プロフィール入力（写真含む）→ 保存 → 「審査中」表示
2. **運営**：事務局画面 → 学生審査タブ → ステータスを「公開中」に（高校生の場合は保護者同意を「確認済み」にも）
3. **企業**：新規登録（種別=企業）→ 企業情報を申請 → 「審査中」表示
4. **運営**：企業審査タブ → 「承認済」に変更
5. **企業**：再読み込み → 学生一覧が表示 → チェック → 詳細 → 「支援を相談」送信
6. **運営**：支援相談タブに案件が届く → ステータスを進める（契約締結まで）
7. **学生**：記録を更新して保存 → **企業**：フィードに「記録を更新：○○ → ○○」が表示されれば全フロー疎通OK

## §6. 公開（GitHub Pages・約10分）

RELIGHTサイトと同じ運用です。

1. GitHubに新規リポジトリ（例：`cosapo`）を作成
2. 配布フォルダ `cosapo/` の中身をそのままアップロード（`index.html`=LP、`app.html`=アプリ本体、`db/`・`docs/`=資料）
3. Settings → Pages → Branch: main で公開（LPが `https://<ユーザー名>.github.io/cosapo/`、アプリが `.../app.html` で公開されます）
4. 公開前に必ず：
   - §4-1の「Confirm email」を**ONに戻す**（なりすまし登録防止）
   - Authentication → URL Configuration の Site URL を公開URLに設定

## §7. 運用上の注意（P1時点の割り切りと次フェーズ）

| 項目 | P1の状態 | 対応フェーズ |
|------|---------|-------------|
| 支援相談の事務局メール通知 | アプリ内の事務局画面で確認（メールは飛ばない）。毎日1回事務局画面の確認を運用ルール化 | P3（Edge Function＋Resendで即時メール化） |
| 顔写真の公開範囲 | 対応済み：非公開バケット＋署名付きURL（ログインユーザーのみ・1時間有効） | 完了 |
| 通知の既読管理 | フィードは新着順表示のみ | P2以降 |
| パスワードリセット | 対応済み：ログイン画面「パスワードをお忘れの方」→再設定メール→新パスワード設定（公開URL上で動作。file://で開いた場合はリンクが戻れないため公開後に利用） | 完了 |

## §8. トラブルシューティング

- **「初期設定が必要です」と表示される** → §3のCONFIG未設定。URLとキーを確認
- **登録したのにログインできない** → 「Confirm email」がONのままの場合、確認メールのリンクを開く必要あり
- **企業でログインしたのに学生が見えない** → 企業ステータスが「承認済」か、学生が「公開中」かを事務局画面で確認（両方必要）
- **写真が表示されない** → §2のSQLが最後まで実行されたか確認（ストレージ設定は後半にあります）
